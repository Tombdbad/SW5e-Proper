# AUDIT 03b: Feature trace, AREA A (Character), 2026-11-07, branch `audit`, read-only

## Plain-English summary
- 22 features traced. **WIRED 10, PARTIAL 8, DEAD 1, MISSING 3, UNKNOWN 0** (WIRED: A-01, 02, 03, 05, 07, 08, 11, 12, 17, 20. PARTIAL: A-04, 06, 09, 10, 13, 18, 19, 22. MISSING: A-14, 15, 16. DEAD: A-21).
- The core character loop is solid and the only part with a real browser test: create a character through the 10 tabs, save, open the sheet, earn XP, take a level, rest, and have the HP and AC come out right (`e2e/play.mjs`). No **unit test** covers character creation or the character-calculation functions themselves; the unit tests that touch `characterCalculation.ts` only import `carriedWeapons`.
- **Five most important problems:**
  1. **Feature effects are mostly text, not rules.** I ran the parsers over every class, archetype and species. Of 218 class features, 92 are resolved into an effect; of 912 archetype features, only **37**; of 739 species traits, **139**. The rest are shown on the sheet and tracked but change no number. (This metric only counts what `featureEffects` and `combatFeatures` resolve. Other code may use some of the rest, e.g. a darkvision trait read elsewhere; I did not check that. See notes under A-10.)
  2. **Multiclassing does not exist**, although the data (`multiclassImprovements.json`) is imported and some fragments sit in the code (A-14).
  3. **Archetypes that grant casting give no powers** (A-15) and **weapon proficiency comes only from the class** (A-16). Both are confirmed in code, not just claimed by the guide.
  4. **`CharacterExportImport.tsx` is never used** by any page (A-21), so there is no way for a player to export/import a character.
  5. **Choosing archetype, fighting style and maneuvers on the character page has no browser test.** The e2e sets those through the API and then tests the fight use (A-04, A-13).
- Guide corrections: GUIDE §11 says "multiclassing" is a gap; true, but not absent from the code (see A-14). GUIDE §4 lists "death saves, conditions" as done; death saves are in `useCombat.ts` and tested; which of the 16 conditions actually do anything was not checked (A-18).

How I judged "Browser-verified": YES only where `e2e/play.mjs` (Playwright, drives the UI) contains a step that does it. I did **not run** the e2e or the unit tests in this session, so "tests pass" is not claimed anywhere. Note `e2e/out/play.log` exists from some earlier run; I did not read it.

## Parser coverage (A-10): how I measured, so it can be repeated

- Method: for every class, a level-20 character with all scores 14; for every archetype, the same with that archetype; for every species, a level-1 Fighter of that species. - Limits: this undercounts, because other code reads some text itself (darkvision, senses, powers, proficiency). The lists of "examples not resolved" above are chosen by even spacing from the unresolved list, not by importance.
