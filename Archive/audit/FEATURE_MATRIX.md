# FEATURE_MATRIX: the merged feature audit (Phase 3c), 2026-11-07, branch `audit`, read-only

## Plain-English summary
- **68% of the 128 features (87) are fully wired** by the audit's static test: the rules data, the code, a screen a player can reach, and at least one test that checks the result (a unit test, or a browser step in `e2e/`). 28 are partial, 11 are missing, 2 are dead code. 0 are unknown.
- "Wired" is a **reading of the code and the tests, not a test run**. I did not run `npm test` or `npm run e2e` in any of these audit phases, so nothing here says the tests pass.
- **All five area files are present and complete** (A 22, B 24, C 30, D 28, E 24 rows = 128; every row of `03_feature_list.md` has a row here). Nothing is missing.
- **Five worst problems:**
  1. Most character features are descriptions, not rules: only 37 of 912 archetype features and 139 of 739 species traits are turned into an effect by the two text parsers (A-10; the count is a lower bound, see A-10 notes).
  2. The AI voice and dialogue pipeline (Gemma, speech to text, Piper) has no test of its own and no browser step (E-01, E-03, E-04).
  3. Multiclassing and mounted combat do not exist (A-14, D-16); archetype casters and species/feat weapon proficiency are not applied (A-15, A-16).
  4. There are no PWA files and no Windows database backup (E-21, E-24); phone play works as a plain web page and a data loss would be unrecoverable.
  5. The project's own guide is out of date in places that hide real work: opportunity attacks and most weapon properties are already implemented (D-06, B-02), while the Downtime tab is test-build only (B-20).
- **Areas ranked by how well wired they are (share of rows WIRED):** 1. World & exploration 83% (25/30), 2. Items & gear 79% (19/24), 3. Combat & vehicles 75% (21/28), 4. Social, AI & systems 50% (12/24), 5. Character 45% (10/22). The first three are strong because every one has unit tests plus the 70-step browser play-through. Character and AI are weakest for opposite reasons: character *rules* are thin, AI parts are *untested*.
- Cross-area check (section 3): 24 interaction chains traced; 15 WIRED, 8 PARTIAL, 1 BROKEN-by-omission (encumbrance is ignored in the shooter; name search only).

Status words: **WIRED** = data + logic + UI + reachable + a test that checks the effect. **PARTIAL** = some link missing (the notes say which). **DEAD** = built but nothing reachable uses it. **MISSING** = promised, not built. Browser column: YES only where an `e2e/*.mjs` step checks the result.

Area files this was merged from: `AUDIT/03_matrix_A.md` to `03_matrix_E.md` (detail, evidence and per-area UNVERIFIED lists live there). Rule applied identically in all five: an e2e step that checks a result counts as a test. (B-19 and B-21 were re-rated from PARTIAL to WIRED on 2026-11-07 to match this rule.)

## 5. Top 20 gaps (PARTIAL, DEAD or MISSING), ranked by how much of normal play they touch
